# 分支开发

> _"分支如小径，各奔目标，终归大道。_"\*

## 核心规则

| 规则             | 说明                                            |
| ---------------- | ----------------------------------------------- |
| **main 保护**    | main 分支始终可发布，禁止直接提交               |
| **develop 日常** | 日常开发在 develop 分支进行                     |
| **功能隔离**     | 每个功能使用独立分支，完成后合并回 develop      |
| **发布标记**     | 使用 release 分支准备发布                       |
| **紧急修复**     | hotfix 从 main 分出，同时合并回 main 和 develop |

## 分支流向图

```
hotfix/* ←─────────┐
                   │
feat/*  ────> develop ────> release/* ────> main ────> tags (v*)
  ↑               │
  └───────────────┘
```

## 工作流详解

**日常开发：**

1. 从 develop 创建 `feat/*` 功能分支
2. 在功能分支上开发、提交
3. 完成后提交 PR 合并到 develop
4. 代码审查通过后合并，删除功能分支

**发布准备：**

1. 从 develop 创建 `release/v*` 分支
2. 进行发布准备（版本号、CHANGELOG、修复 bug）
3. 合并到 main 并打标签
4. 合并回 develop
5. 删除 release 分支

**紧急修复：**

1. 从 main 创建 `hotfix/*` 分支
2. 修复问题并测试
3. 合并到 main 并打新标签
4. 合并回 develop
5. 删除 hotfix 分支
