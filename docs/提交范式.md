# 提交范式

## 核心原则

> _"好的提交信息应该回答：做了什么，为什么做。"_

1. **原子化提交** — 每次提交只做一件事
2. **清晰即正义** — 信息应该让人一目了然
3. **历史即文档** — 提交历史本身就是项目文档
4. **杜绝 WIP** — 不提交未完成的工作

## 基本结构

```
<类型>(<范围>): <简短描述>

<详细描述>

<页脚>
```

## 类型（Type）

| 类型       | 图标 | 说明                          | 示例                |
| ---------- | ---- | ----------------------------- | ------------------- |
| `feat`     | ✨   | 新功能                        | 添加英雄系统        |
| `fix`      | 🐛   | Bug 修复                      | 修复战斗数值错误    |
| `docs`     | 📚   | 文档更新                      | 更新 README         |
| `style`    | 💄   | 代码风格（不影响功能）        | 统一缩进格式        |
| `refactor` | ♻️   | 重构（不是新功能也不是修复）  | 重构状态机          |
| `perf`     | ⚡   | 性能优化                      | 优化渲染性能        |
| `test`     | ✅   | 测试相关                      | 添加单元测试        |
| `build`    | 📦   | 构建系统或外部依赖            | 更新依赖版本        |
| `ci`       | 👷   | CI 配置文件和脚本             | 添加 GitHub Actions |
| `chore`    | 🔧   | 其他不修改 src 或 test 的更改 | 更新配置文件        |
| `revert`   | ⏪   | 回退提交                      | Revert "feat: xxx"  |
